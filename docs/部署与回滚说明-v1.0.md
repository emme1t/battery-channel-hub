# Battery Channel Hub 部署与回滚说明

本文说明程序和 SQLite 数据切换的安全边界，不构成生产操作授权。默认流程为只读检查；任何写入正式目录的操作都必须由操作者再次明确批准。

## 1. 发布前检查

1. 在目标提交运行 `npm ci`、`npm test`、目录构建和 NSIS 构建。
2. 核对候选程序、候选 SQLite 和交付文件的 SHA-256。
3. 在隔离 Windows 环境验证安装、启动、主程序入口、卸载入口和数据保留。
4. 确认正式应用及其子进程已停止，SQLite 不存在活动 WAL、SHM、journal 或文件句柄。
5. 外部备份目录必须位于正式数据目录之外。

任一条件不满足都应停止，不得通过修改报告、数据库或 sidecar 绕过检查。

## 2. 数据切换 dry-run

使用规范化后的精确绝对路径运行：

```powershell
node scripts/switch-production-sqlite.mjs `
  --candidate <候选SQLite> `
  --data-root <正式数据目录> `
  --backup-root <外部备份目录> `
  --active-program <当前程序> `
  --candidate-program <候选程序>
```

不带 `--apply` 时必须保持只读，不创建报告、归档、备份、staging 或目标文件。以下任一结果均为停止条件：

- 路径不存在、越界或所有权不明确；
- 正式应用仍运行或文件句柄未释放；
- 候选哈希、SQLite 完整性或预期计数不匹配；
- 外部备份位于正式数据目录内部；
- 程序与数据库候选无法证明属于同一批次。

## 3. 执行切换

只有 dry-run 无错误、外部备份位置和候选哈希均已人工复核，并取得明确批准后，才在完全相同的命令末尾添加：

```text
--apply
```

执行后保存 run id、报告、切换前后程序/数据库配对关系及所有哈希。重新打开 SQLite，核验完整性、revision、设备/通道计数和关键业务集合，再用候选程序读取正式数据。

## 4. 回滚预检查

回滚使用已完成切换的 run id：

```powershell
node scripts/switch-production-sqlite.mjs `
  --data-root <正式数据目录> `
  --backup-root <外部备份目录> `
  --active-program <当前程序> `
  --rollback <run-id>
```

不带 `--apply` 时只做回滚预检查。必须验证切换报告、外部备份、当前活动数据库、归档程序和数据库代际关系。预检查失败时不得继续。

确认无误并获得明确批准后，才在同一回滚命令末尾添加 `--apply`。回滚完成后重新核验 SQLite 完整性、业务集合、程序入口和文件哈希。

## 5. 失败处理

- 任一阶段失败时停止后续替换，保留报告、备份和当前文件。
- 不手工编辑 SQLite、WAL/SHM、generation lineage、切换报告或哈希清单。
- 不在来源目录、工作区根目录或用户主目录执行递归清理。
- 优先恢复到最后一个已经验证的程序/SQLite 配对，再重新执行只读预检查。
- 若无法证明备份、程序和数据库的对应关系，不执行回滚写入。

代码合并、构建成功或安装包生成都不等于生产部署已完成。
