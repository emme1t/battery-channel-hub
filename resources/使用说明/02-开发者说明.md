# Battery Channel Hub 开发者说明

面向对象：接手维护、排错、扩展、测试和打包本软件的人类开发者

文档日期：2026-09-03
文档地址：`resources\使用说明\02-开发者说明.md`

## 1. 文档范围

本文说明当前 Battery Channel Hub Electron 主程序的代码组织、运行入口、状态模型、SQLite 持久化、IPC、导入导出、测试和打包方式。本文不是生产部署授权，也不表示某个历史测试记录仍然代表当前代码。任何发布结论都必须基于目标提交上的新鲜测试、目标产物哈希和隔离环境验收。

本软件是本地离线的电池测试通道管理工具，不直接连接、采集或控制真实测试设备。设备、通道、预约、测试和长期存储均为管理状态；任何真实设备联控都属于新的安全边界，不能直接塞进现有渲染层实现。

## 2. 获取代码与核验当前快照

公开源码仓库：`https://github.com/emme1t/battery-channel-hub`

接手时不要依赖说明文档中的历史测试数字。先在目标工作树执行：

```powershell
git status --short --branch
git log -5 --oneline --decorate
git remote -v
```

工作树可能包含用户未提交的改动。不要使用 `git reset --hard`、`git checkout -- .` 或批量清理命令覆盖用户内容。

## 3. 技术栈与运行入口

- 桌面容器：Electron 37
- 运行时：Node.js，主进程使用 CommonJS 与动态 ESM 混合加载
- 数据库：Node 内置 `node:sqlite` 的 `DatabaseSync`
- 表格：SheetJS `xlsx`
- 打包：`electron-builder`
- 自动测试：Node Test Runner、Playwright Core、Electron/Edge 驱动脚本
- 主页面：`电池测试通道预约Demo.html`
- 主进程入口：`main.js`
- 预加载桥：`preload.js`
- 旧 MAIN 增量交互：`feedback_patch.js`

`src/renderer/index.html`、`app.mjs` 等文件属于另一套模块化渲染实现和演进证据。当前正式 Electron 窗口由 `main.js` 加载根目录的 `电池测试通道预约Demo.html`，维护者不能只修改 `src/renderer/index.html` 就认为主程序已经变化。每次 UI 修改都应从 `main.js` 的真实 `loadFile()` 入口向下追踪。

窗口安全配置当前为：

- `contextIsolation: true`
- `nodeIntegration: false`
- 通过 `preload.js` 暴露受限 API
- 单实例锁：第二次启动只聚焦现有窗口

当前 `sandbox: false`。如果将来启用 Electron sandbox，需要重新验证预加载能力、文件对话框、SQLite 和自动测试，不应把它当作无风险配置开关。

## 5. 主进程、预加载与 IPC

主进程启动时依次创建 SQLite store、预约命令服务、长期存储服务、申请服务、Excel 文件对话框、及时率 PNG 服务和备份服务，然后注册 IPC。

当前主要 IPC 通道：

| IPC 通道 | 作用 |
|---|---|
| `state:load` | 读取完整规范化状态 |
| `state:save` | 以 `expectedRevision` 保存状态和表单日志 |
| `reservation:execute` | 预约、立即开始、通道转换、运行中普通测试退回、已预约记录退回 |
| `storage:execute` | 长期存储开始、更新、完成和退回 |
| `application:execute` | 申请相关命令 |
| `excel:import` | 选择并导入单个 Excel/CSV 文件 |
| `excel:import-folder` | 递归导入文件夹 |
| `excel:export` | 导出 XLSX |
| `dashboard:export-png` | 导出测试及时率 PNG |
| `state:backup` | 导出 `.batterydata` 或 `.json` 备份 |
| `state:restore` | 校验并恢复备份 |

`preload.js` 在 `window.batteryDesktop` 下暴露有限方法，不应把任意 `ipcRenderer`、文件系统或数据库句柄直接暴露给页面。新增 IPC 时至少做到：

1. 页面只发送可结构化克隆的数据。
2. 主进程验证命令类型、字段、revision 和业务约束。
3. 主进程返回结构化成功/失败对象。
4. 渲染层只在主进程确认持久化成功后更新权威状态。
5. 添加失败路径和并发冲突测试。

预加载层用 `saveTail` 串行化保存、预约、长期存储、申请和恢复操作，避免同一窗口中的写请求乱序。不要绕过这些包装函数直接从页面同时调用多个写 IPC。

## 6. SQLite 持久化

数据库文件名：`battery-channel-hub.sqlite`

数据目录规则：

- 打包程序：`app.getPath('userData')\data`
- 未打包开发模式：默认仓库 `data` 目录
- 未打包且设置 `BATTERY_CHANNEL_DATA_DIR`：使用该环境变量指定的绝对目录

开发、测试和候选验收必须设置独立临时数据目录，禁止直接打开正式 userData：

```powershell
$env:BATTERY_CHANNEL_DATA_DIR = Join-Path $env:TEMP 'battery-channel-hub-dev'
npm start
```

SQLite store 当前使用两个核心表：

- `app_state`：保存完整 JSON payload、revision 和更新时间。
- `form_change_journal`：保存独立、可去重的表单变更审计记录。

保存过程使用 `BEGIN IMMEDIATE`，读取当前 revision，校验 `expectedRevision`，写入下一 revision，并在同一事务写入状态和日志。revision 不一致时返回 `REVISION_CONFLICT`，不得用“再覆盖一次”的方式吞掉冲突；应重新加载最新状态，让用户重新确认业务动作。

对数据库文件做复制或切换时，必须把 SQLite 主文件、`-wal`、`-shm` 和可能存在的 journal 视为一个证据组。运行中的数据库不能靠单独复制主文件宣称备份成功。优先使用 GUI 备份或仓库内经过验证的切换工具。

## 7. 状态模型与业务不变量

规范化状态的主要集合：

- `requests`：申请单
- `samples`：逐块电池子样品
- `deviceProfiles`：设备
- `channels`：设备通道
- `records`：普通预约/测试使用记录
- `storageRecords`：长期存储记录
- `requestSourceRows`：导入原始行证据
- `auditLogs`：操作审计
- `formChangeJournal`：表单变更日志
- `testers`：测试人员

关键不变量：

1. 申请单号就是批号。
2. 数量 `N` 必须是 1–999 的整数。
3. 子样品编号为 `申请单号.001` 到 `申请单号.NNN`。
4. 一块电池对应一个子样品，一条有效通道映射。
5. 同一通道同一时间只能由一块电池占用。
6. 同一子样品不能同时处于普通预约/测试和有效长期存储中。
7. 批量预约或开始必须全部成功或全部不写入，不能部分落库。
8. 运行中普通测试退回必须释放精确的当前通道所有权；已预约记录退回必须释放 booked 通道或只清除 busy 通道的后续预约；长期存储退回不改变通道。三类退回都必须保留原因和 canonical 审计。
9. 设备 id、设备名称、通道 key、样品 id 和长期存储 id 必须唯一。

状态规范化集中在 `src/main/legacy-state-schema.mjs`，业务转换集中在 `src/domain/`。新增状态或迁移规则时，应先在规范化层和纯 domain 函数中定义，再接主进程命令服务和 UI；不要在点击事件里直接拼接一份“看起来正确”的完整状态。

## 8. 导入、导出和文件契约

### 8.1 申请导入

生产解析器位于 `src/main/excel-service.mjs`，支持：

- `.xlsx`
- `.xls`
- `.csv`

安全上限：单文件 25 MB，单工作表 50,000 行。文件夹导入会递归遍历支持格式并跳过 `~$` 锁文件。

支持两种结构：

- 纵向字段表：字段名/填写内容。
- 横向汇总表：首行为列名，每行一张申请单。

导入记录同时保留 `rawFields`、来源文件名和来源路径。执行阶段的修改使用 `editedFields`，不要覆盖原始导入证据。导出时根据实际字段生成动态列：原始导入值使用 `原始_*`，执行阶段当前值使用 `当前_*`；固定业务列不能替代这两组证据列。

### 8.2 GUI 导出

- 申请汇总 `.xlsx`：`测试申请表格`、`测试项目明细`；使用页面开始/结束日期按当前 `execution.plannedEnd` 做包含边界的筛选，两端都留空时导出全部申请，倒置或无匹配范围不调用 Excel 导出
- 勾选申请 `.xlsx`：`选中申请表格`；沿用申请汇总的动态 `原始_*`、`当前_*` 列合同
- 日志 `.xlsx`：`日志`、`使用记录`、`测试设备使用表2`、`通道当前状态`；使用记录状态读取 canonical `status`
- 测试及时率 `.png`
- 完整数据备份 `.batterydata` 或 `.json`

Excel 导出采用临时文件、写后重读和工作表/行数/公式错误核对。不要把 `XLSX.writeFile()` 返回无异常直接当成导出成功。新增导出表时应同步更新 GUI、服务测试、附件样式和用户说明。

### 8.3 备份格式

`.batterydata` 与 `.json` 是同一 JSON 数据模型，仅扩展名不同。备份包包含格式名、版本、创建时间、原因、source revision、规范化 state 和 `stateSha256`。恢复流程先校验 SHA-256 和 revision，并在替换前生成恢复前备份。

不要手工编辑备份包后重新计算哈希来绕过校验；那会破坏审计边界。格式升级应增加明确版本和迁移逻辑，并保留旧版恢复测试。

本说明配套的全部格式样例位于：`resources\使用说明\文件样式`

## 9. 本地开发

建议使用 PowerShell：

```powershell
git clone https://github.com/emme1t/battery-channel-hub.git
Set-Location -LiteralPath '.\battery-channel-hub'
npm ci
$env:BATTERY_CHANNEL_DATA_DIR = Join-Path $env:TEMP 'battery-channel-hub-dev'
npm start
```

依赖锁文件为 `package-lock.json`。更新依赖时应同时提交 `package.json` 和 `package-lock.json`，并重新执行核心测试、Electron Smoke 和打包内容检查。

开发时建议每个任务使用独立数据目录。测试后清理临时数据可以由测试脚本负责；不要编写指向用户正式目录的递归删除命令。

## 11. 打包

```powershell
npm run dist:dir
npm run dist
npm run dist:installer
```

产物约定：

- `dist\win-unpacked\电池测试通道预约与使用看板.exe`
- `dist\Battery-Channel-Hub-1.0.0-portable.exe`
- `dist\Battery-Channel-Hub-1.0.0-setup.exe`

`dist:dir` 适合快速检查 unpacked 内容；Portable 和 NSIS 还需要各自的启动、安装、卸载和数据保留验收。`build.nsis.deleteAppDataOnUninstall` 必须显式保持为 `false`，避免构建器默认值变化导致卸载时删除 SQLite；真实保留行为仍需在隔离 Windows 环境验证。当前构建配置未提供代码签名工具链，不能把“成功生成 EXE”描述为“已签名可正式发布”。

打包内容由 `package.json` 的 `build.files` 白名单决定。新增运行时模块后，必须同步加入白名单并运行 `tests/package-contents.test.mjs` 或相应包证据脚本，否则源码测试可能通过但 ASAR 中缺文件。

## 12. 生产切换和回滚

生产切换是高风险外部状态变更，必须先阅读：

`docs\部署与回滚说明-v1.0.md`

仓库脚本 `scripts/switch-production-sqlite.mjs` 默认执行 dry-run。只有在以下条件全部满足后，操作者才能明确批准 `--apply`：

- 应用及子进程已停止；
- SQLite sidecar 和文件句柄已核对；
- 候选程序、候选 SQLite、正式目录和外部备份目录均为精确绝对路径；
- 备份位于正式数据目录之外；
- 候选和备份 hash 已复核；
- 隔离人工回归通过；
- 回滚 run-id 和成对程序/数据库归档已确认。

不得把代码合并、打包成功或桌面快捷方式更新解释为生产切换授权。

新 switch report 使用不可变 generation lineage：report、run 专属 `generation-lineage.json` 与 SQLite 的不可更新 lineage 行必须精确一致。该规则允许同一代的正常业务保存，但拒绝另一切换代、sidecar 篡改或报告不一致；rollback apply 先把当前新代完整保存为 `after-switch.sqlite` 并重新验证。历史无 lineage 报告保留严格整文件 hash 兼容路径。开发者不得手工编辑 sidecar、report、SQLite lineage 或 `after-switch.sqlite` 来绕过所有权与恢复边界。

## 13. 修改流程建议

1. 明确目标入口和业务不变量。
2. 从现有测试复现当前行为或失败。
3. 优先在 `src/domain/` 添加纯业务测试和最小实现。
4. 在 `src/main/` 接入 revision、事务和结构化错误。
5. 通过 `preload.js` 的有限 API 接入正式页面。
6. 运行受影响测试、`git diff --check` 和必要 Electron 回归。
7. 若影响文件格式，更新 `resources\使用说明` 的样例和说明。
8. 若影响打包，检查 `build.files` 和 ASAR 内容。
9. 若影响数据模型，提供旧数据兼容、备份恢复和失败回滚证据。

## 14. 发布前最低检查表

- Git 目标提交明确，工作树差异已审查。
- 核心测试、相关 Smoke、Edge/Workflow 门禁按风险运行。
- 所有十个页面可打开，关键输入框可在真实 Electron 中键入。
- 普通预约、立即开始、正在测试退回、已预约记录退回、长期存储和长期存储退回通过；立即开始和预约均拒绝 `结束时间 <= 开始时间`，修正后可继续，重启后状态一致。
- `.xlsx`、`.xls`、`.csv` 导入通过。
- 三类 XLSX 导出和及时率 PNG 可独立打开。
- `.batterydata`、`.json` 备份可校验恢复，篡改包被拒绝。
- 关闭重开后 SQLite 状态、审计和通道占用一致。
- 产物内容、hash、签名状态和版本号已记录。
- Portable、NSIS、卸载和数据保留在隔离环境验收。
- 已准备可执行回滚方案，但未在无授权情况下操作正式数据。
